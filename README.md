# Joe MCP Node - Rust

This directory contains the Rust managed-node package used by Joe MCP Server. The public customer-facing repository is:

`https://github.com/youssefdaoud23/joe-mcp-node-rust`

A Joe node is not a second MCP server. It is a managed Linux agent that connects outbound to the central Joe MCP controller and executes only the operations permitted by its local/device policy.

## Which repository should I use?

Use the private server repository when deploying the Joe controller:

`youssefdaoud23/joe-mcp-server-rust`

A fresh Rust controller now has a bootstrap installer. On the controller host, clone the server repo, copy `.env.example` to `.env`, set `JOE_RUST_PUBLIC_URL`, then run `sudo ./install.sh`. The server README and `docs/INSTALL.md` explain every file, environment value, runtime path, HTTPS step and ChatGPT connection step.

Use this node package/public repository when installing or reviewing the managed Linux agent:

`youssefdaoud23/joe-mcp-node-rust`

The public node repository intentionally does not contain the full private controller workspace or controller secrets.

## Recommended node installation

You normally do not need to clone this repository onto a managed device.

The recommended installation flow is:

1. Deploy the Rust Joe MCP controller first.
2. Sign in to the Joe Admin or User UI.
3. Open **Devices -> Add device**.
4. Choose the access mode and permissions for the machine.
5. Copy the short-lived one-time installation command generated by Joe.
6. Run it with sudo/root on the Linux device.

The generated command looks similar to:

```bash
curl -fsSL https://mcp.example.com/install-rust | \
  sudo bash -s -- --server https://mcp.example.com --enroll ONE_TIME_CODE
```

The one-time enrollment code is generated by the controller and expires. Do not reuse or publish it.

## Node requirements

The managed node currently requires:

- Linux;
- systemd;
- root/sudo for installation;
- `curl`;
- `sha256sum`;
- outbound HTTPS access to the Joe MCP controller.

The node does not require Docker and does not open an inbound management port.

## What the installer does

The installer:

1. downloads `joe-mcp-rust-agent` and `joe-mcp-rust-updater` from the configured Joe controller;
2. downloads their SHA-256 checksum files;
3. verifies the binaries before installation;
4. enrolls the node with the short-lived one-time code;
5. writes the node configuration under `/var/lib/joe-mcp-rust-agent/`;
6. installs the agent and updater binaries under `/usr/local/libexec/`;
7. installs the systemd units;
8. enables and starts the managed-node agent.

Installed paths:

```text
/usr/local/libexec/joe-mcp-rust-agent
/usr/local/libexec/joe-mcp-rust-updater

/var/lib/joe-mcp-rust-agent/config.json
/var/lib/joe-mcp-rust-agent/update-status.json
/var/lib/joe-mcp-rust-agent/update-backups/

/etc/systemd/system/joe-mcp-rust-agent.service
/etc/systemd/system/joe-mcp-rust-update.service
```

The node stores its device credential locally. Do not copy the config file between machines.

## Clone this repository for inspection or manual installation

If you want the node source/install assets locally:

```bash
git clone https://github.com/youssefdaoud23/joe-mcp-node-rust.git
cd joe-mcp-node-rust
```

Verify the exported files against the repository manifest:

```bash
sha256sum -c MANIFEST.sha256
```

The public node repository is an exported distribution/source-review repository. It is not the complete private Rust Cargo workspace used to build official release binaries. Official binaries are built from `joe-mcp-server-rust` and served checksum-pinned by the controller.

## Run the cloned installer manually

You still need a valid one-time enrollment code from **Devices -> Add device** in the controller.

Then run:

```bash
sudo bash scripts/install-node.sh \
  --server https://mcp.example.com \
  --enroll ONE_TIME_CODE \
  --name my-linux-node
```

`--name` is optional. If omitted, the installer uses the machine hostname.

The controller URL must be HTTPS.

## Verify the installation

```bash
systemctl status joe-mcp-rust-agent.service --no-pager
journalctl -u joe-mcp-rust-agent.service -n 100 --no-pager
```

The service should be active/running.

Then return to the Joe UI and confirm the device appears online under **Devices**.

## How the node communicates

The node initiates an outbound HTTPS connection/polling flow to the Joe controller.

```text
ChatGPT
   |
   v
Joe MCP Server
   |
   | authenticated managed-device routing
   v
Joe Rust Agent on Linux node
   |
   v
local host tools and policy
```

The controller never needs SSH access to the node for normal operation.

## Access policy

When adding the device, Joe can configure access as:

- **Full** - broad Joe tool availability, still subject to host safety controls;
- **Restricted** - only selected filesystem roots and permissions;
- **Custom** - explicit per-category permissions.

The node enforces local/device policy even if the controller or ChatGPT asks for more access.

Developer Access and temporary sudo are separate opt-in administrative features and are off unless explicitly enabled.

## Updating a node

The preferred method is from the Joe UI using the managed update action.

The updater:

1. snapshots the current installed agent/updater;
2. downloads new checksum-verified binaries;
3. replaces the runtime;
4. restarts and verifies the agent service;
5. automatically restores the previous binaries if activation fails.

You can also invoke the installed update unit manually:

```bash
sudo systemctl start joe-mcp-rust-update.service
```

Check update status with:

```bash
sudo systemctl status joe-mcp-rust-update.service --no-pager
sudo cat /var/lib/joe-mcp-rust-agent/update-status.json
```

Do not manually overwrite the official agent binary if you want rollback-aware managed updates to remain reliable.

## Reinstalling or migrating an existing node

Running the installer again on a machine with an existing valid Rust configuration preserves the existing device identity rather than creating a new device, unless the local configuration has been removed/revoked.

When the Rust installer runs on a legacy Python-generation Joe node and no Rust config or new enrollment code is supplied, it validates the legacy controller origin and imports that node's existing device ID, device credential and name into the protected Rust config. The Rust agent marks the handoff as pending, proves it can authenticate to the controller, waits for any legacy updater run to finish, and only then disables and stops the old Python node-agent unit so only Rust survives reboot. The legacy unit and files remain installed as an explicit rollback path until Rust parity, update and reboot checks are complete. Rollback is deliberate: disable the Rust agent, then re-enable and start the legacy Python agent.

Use the current controller URL:

```bash
curl -fsSL https://mcp.example.com/install-rust | \
  sudo bash -s -- --server https://mcp.example.com
```

For a completely new enrollment, generate a fresh command from **Devices -> Add device**.

## Moving the controller to another server/domain

If the Joe controller is redeployed somewhere else, the node must be able to reach the new HTTPS origin.

For a clean migration, use the new controller's **Devices -> Add device** flow and enroll the machine against that controller. Do not copy another node's credential file.

If preserving the same Joe database/device identity and the public Joe URL remains unchanged, the node can normally reconnect without re-enrollment.

## Uninstalling a node

First revoke/remove the device from the Joe controller if it is still registered.

Then on the Linux machine:

```bash
sudo systemctl disable --now joe-mcp-rust-agent.service || true
sudo rm -f /etc/systemd/system/joe-mcp-rust-agent.service
sudo rm -f /etc/systemd/system/joe-mcp-rust-update.service
sudo rm -f /usr/local/libexec/joe-mcp-rust-agent
sudo rm -f /usr/local/libexec/joe-mcp-rust-updater
sudo rm -rf /var/lib/joe-mcp-rust-agent
sudo systemctl daemon-reload
```

Only delete `/var/lib/joe-mcp-rust-agent` if you intentionally want to remove the node's local identity and update history.

## Troubleshooting

### Agent not running

```bash
systemctl status joe-mcp-rust-agent.service --no-pager
journalctl -u joe-mcp-rust-agent.service -n 200 --no-pager
```

### Test controller reachability

```bash
curl -fsS https://mcp.example.com/health
```

### Check the installed files

```bash
ls -l /usr/local/libexec/joe-mcp-rust-agent
ls -l /usr/local/libexec/joe-mcp-rust-updater
sudo ls -l /var/lib/joe-mcp-rust-agent/
```

### Device appears offline

Check:

- DNS resolution;
- outbound HTTPS/firewall rules;
- system time;
- the agent service logs;
- whether the device was revoked in the controller;
- whether the controller public URL changed.

## Security

- Never publish an enrollment code.
- Never commit `/var/lib/joe-mcp-rust-agent/config.json`.
- Never copy one device credential onto another machine.
- Use only HTTPS controller URLs.
- Treat Developer Access/root/sudo as high-risk opt-in features.
- Keep the node outbound-only unless you have a separate reason to expose services on that host.

See `SECURITY.md` for additional repository-specific guidance.
